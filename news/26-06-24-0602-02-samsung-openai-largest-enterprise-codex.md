# Samsung ปูพรม ChatGPT Enterprise + Codex ทั่วองค์กร — deal ที่ใหญ่ที่สุดของ OpenAI

## TL;DR
- 21 มิ.ย. 2026 OpenAI ประกาศ Samsung Electronics ให้พนักงาน Korea ทั้งหมด + Device eXperience (DX) ทั่วโลกใช้ ChatGPT Enterprise + Codex
- OpenAI เรียกเองว่า "หนึ่งใน enterprise launch ที่ใหญ่ที่สุดที่เคยมี" — DX division มีพนักงานหลายหมื่นคนข้ามทวีป
- Codex-Maxxing: 20% ของ user ปัจจุบันเป็น non-developer และโตเร็วกว่า dev 3 เท่า — OpenAI กำลังเปลี่ยน positioning Codex จาก coding tool เป็น automation platform

## เกิดอะไรขึ้น

วันที่ 21 มิถุนายน OpenAI ประกาศดีล Samsung Electronics ซึ่งครอบคลุมพนักงานทั้งหมดในเกาหลี + ทุกคนใน Device eXperience (DX) division ทั่วโลก. DX คือ business unit ที่ทำ Galaxy smartphone, home appliance, consumer electronics — พนักงานหลักหมื่นคนกระจายในหลายทวีป. OpenAI ออกมาเคลมตรง ๆ ว่า "this is one of OpenAI's largest enterprise launches ever" ซึ่งหมายถึงทั้ง seat count และ scope ของ tool ที่ deploy.

จุดที่ underreported คือ Samsung ไม่ได้แค่ ChatGPT Enterprise — Codex มาด้วย. และ Samsung ไม่ได้ deploy Codex แค่ engineering team. ในข่าวประกอบ OpenAI เปิดเผยตัวเลขที่น่าตกใจ: knowledge worker ที่เป็น non-developer ตอนนี้คิดเป็น 20% ของ Codex user base ทั้งหมด — และโตเร็วกว่า developer user 3 เท่า. นี่คือเหตุผลที่ Samsung deploy Codex ไป non-engineering ด้วย — marketing, HR, finance ใช้ Codex สร้าง internal tool, website, automated workflow โดยไม่ต้องผ่าน IT request queue. สื่อ tech ตั้งชื่อ trend นี้ว่า "Codex-Maxxing" — การที่ tool สำหรับ developer ถูก stretch ออกไปเป็น general productivity layer.

Context ที่ทำให้ deal นี้สำคัญ: Samsung เป็น Korea conglomerate ที่ตอนแรกสุดของ ChatGPT boom เคยแบนการใช้ generative AI ภายในหลังเกิดเหตุ leak source code. 2 ปีกว่า — จาก blanket ban ไปสู่ enterprise-wide rollout บน OpenAI flagship product. ระยะเวลาที่ enterprise risk appetite พลิกจาก "ห้าม" เป็น "default tool" สั้นมาก.

## ทำไมสำคัญ

ปีนี้คือปีที่ enterprise AI seat license หยุดเป็น pilot และเริ่มเป็น platform deal ระดับ Microsoft 365. Samsung deal นี้คล้าย ChatGPT Enterprise pattern ที่เราเห็นกับ Morgan Stanley และ Bain ก่อนหน้านี้ — แต่ scale ใหญ่กว่าและรวม Codex เข้าไปเป็น default. นั่นแปลว่า OpenAI ไม่ได้ขาย ChatGPT-as-chatbot อีกแล้ว มันขาย "AI workforce layer" ที่มีทั้ง conversation surface และ code-execution surface ในแพ็คเดียว.

ตัวเลข "20% non-developer, 3x growth" คือ signal ที่สำคัญที่สุดในประกาศนี้. มันบอกว่า boundary ระหว่าง "developer tool" กับ "office productivity tool" กำลังพัง. ใน 12 เดือนข้างหน้า เราจะเห็นคำว่า "vibe coder" หรือ "citizen developer" ค่อย ๆ ไร้ความหมายเพราะ ทุก knowledge worker จะมี IDE-like surface ในมือ. ใครที่ขาย no-code/low-code platform แบบเดิม ๆ ต้องคิดใหม่ — value prop ไม่ใช่ "ไม่ต้องเขียน code" อีกแล้ว แต่เป็น "เขียน code อะไรก็ได้ในภาษาที่อยากเขียน". มี POV ตรงนี้: Samsung deal เป็นเครื่องบ่งชี้ว่า horizontal LLM platform กำลังกินตลาดของ horizontal productivity platform ในแนวทแยง.

ที่ต้องระวัง: OpenAI ไม่เปิด pricing ดีลนี้ และ "ทุกคนใน Korea" เป็นคำที่ค่อนข้าง vague — Samsung Korea มีพนักงานราว ๆ 110,000 คน แต่ DX division ทั่วโลกตัวเลขแน่ ๆ ไม่ออก. "largest ever" จึงต้องวัดเทียบ deal ที่เคยมีของ OpenAI ที่เปิดเผย (เช่น JPMorgan 200K seats, PwC 100K) — likely ใหญ่กว่าทั้งคู่ แต่ไม่มี third-party verification.

## มุม OpenBridge

ดีลแบบนี้สร้าง pattern สำคัญสำหรับ B2B SaaS ในเอเชีย: AI deployment ที่ใช้ตัดสินใจคือ procurement ระดับ CEO/CTO ไม่ใช่ developer adoption แบบ bottom-up. OpenBridge ที่ targeting mid-market ในไทย/SEA ควรคิดว่า — เมื่อ enterprise IT department ของ conglomerate เริ่มซื้อ AI tool ระดับ org-wide เขาจะต้องการ "integration layer" ที่เชื่อม internal data + SaaS + agent — ไม่ใช่ point-to-point connector. นี่คือโอกาสที่ integration platform จะ position ตัวเองเป็น "control plane" ของ agent rollout แทนที่จะเป็นแค่ webhook router.

Insight ที่สอง: ถ้า Codex non-developer adoption โต 3x เร็วกว่า developer แปลว่ามี population ใหม่ของ "people who write small code daily" ที่กำลังเกิดขึ้น. คนกลุ่มนี้ต้องการ deploy script ที่เขียนเองไปยัง internal SaaS ของบริษัท — connector + auth + scheduling — ตรงนี้คือ wedge ที่ integration tool สามารถจับ. ลองคิด feature แบบ "publish your Codex-generated script as a workflow บน OpenBridge" — เป็น GTM motion ที่ leverage organic Codex adoption แทนการแย่ง developer mind share.
