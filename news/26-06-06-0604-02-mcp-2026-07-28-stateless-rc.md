# MCP ลบ session handshake ทิ้ง — RC ใหม่ 2026-07-28 = revision ใหญ่ที่สุดตั้งแต่ launch, รื้อ enterprise deployment ใหม่ทั้งหมด

## TL;DR
- Model Context Protocol ปล่อย **release candidate 2026-07-28** สัปดาห์ที่ผ่านมา — **revision ใหญ่ที่สุดตั้งแต่ launch** Nov 2024
- หัวใจคือ **stateless protocol core** — ลบ initialize handshake ทิ้ง, ทุก request self-contained, **run ได้บน plain round-robin load balancer แทน sticky session + shared session store**
- แถม 2 official extension: **MCP Apps** (server ship HTML UI ที่ host render ใน sandboxed iframe), **Tasks** (long-running work ด้วย task handle + polling) — ทั้งคู่ promote จาก experimental
- Scale ปัจจุบัน: **97M monthly SDK downloads (Python + TypeScript)** — adopted ทั้ง Anthropic, OpenAI, Google, Microsoft, Amazon. Donated เข้า Agentic AI Foundation under Linux Foundation แล้ว

## เกิดอะไรขึ้น

ช่วงสัปดาห์ที่ผ่านมา ทีม core ของ Model Context Protocol publish **release candidate ของ spec 2026-07-28** — เป็นการประกาศชัด ๆ ว่า RC นี้คือ "**largest revision since launch**" ของ protocol ที่ Anthropic เปิดเมื่อปลายปี 2024 และตอนนี้กลายเป็น de-facto standard สำหรับ agent-to-tool communication ไปแล้ว

หัวใจของการ revision คือ **stateless protocol core**. ใน MCP 2025 spec, client ต้องเริ่มทุก connection ด้วย `initialize` handshake — server เก็บ session state ไว้ตลอด — เวลา deploy production ต้องใช้ **sticky sessions, shared session store, deep packet inspection ที่ gateway** เพื่อให้ load balancer ส่ง request กลับไปที่ instance เดิมได้. RC นี้ลบทิ้งหมด: ทุก request **self-contained** — protocol version, client info, capabilities เดินทางใน `_meta` ทุก request — **server instance ไหนก็ตอบได้ทุก request**, route ตาม `Mcp-Method` header, cache `tools/list` response ได้ตาม `ttlMs` ที่ server กำหนด

ของแถมที่สำคัญพอกัน: **2 extensions ที่ formalize**. (1) **MCP Apps** — server ส่ง interactive HTML UI ให้ host render ใน sandboxed iframe, tool declare UI template ล่วงหน้าให้ host prefetch + security review ก่อน — UI ที่ render คุยกับ host ผ่าน JSON-RPC base protocol ตัวเดียวกันทุก action, **ทุก UI-initiated action ผ่าน audit + consent path เดียวกับ direct tool call**. (2) **Tasks** — เดิมเป็น experimental ใน spec 2025-11-25, production use เผยว่าออกแบบไม่พอ ย้ายไปเป็น extension. Server ตอบ `tools/call` ด้วย task handle, client ขับด้วย `tasks/get`, `tasks/update`, `tasks/cancel` — server เป็นคนเลือกว่า request ไหน should run as task

ที่เซอร์ไพรส์ practitioner คือ **MCP Sampling ถูก deprecate** — feature ที่ให้ server ขอ LLM call ผ่าน client ที่ใช้กันใน research agent / multi-step reasoning. Maintainer บอกว่า "ใช้น้อย, สร้าง security ambiguity เยอะ, ของอนาคตคือ server-as-agent ที่ทำ orchestration เอง" — Nullpointer Blog เขียนตอบกลับว่า "deprecate sampling = ตัดอำนาจ host แล้วโยนให้ server" — เห็นได้ว่ายังไม่ consensus

ส่วน OAuth + OpenID Connect alignment ที่ทำใน authorization layer คือ **enterprise feature ที่ Cloudflare + WorkOS ผลักดันหลังจาก enterprise MCP gateway market โต**. RC นี้รวม draft จาก Cloudflare Pull Request หลายตัวที่ค้างมา 3 เดือน

## ทำไมสำคัญ

นี่คือ **MCP 2.0 moment** — protocol ที่ 18 เดือนที่แล้วยังเป็น Anthropic-only ตอนนี้ตัดสินใจ refactor ใต้ governance ของ Agentic AI Foundation (Linux Foundation) ที่ Anthropic donate ให้ ปัจจุบัน OpenAI + Block เป็น co-founder, AWS, Google, Microsoft, Cloudflare, GitHub, Bloomberg เป็น supporting member. **Cross-vendor protocol ที่ทุก hyperscaler ลงนามจริงในรอบหลายปี** ไม่มีใน Kubernetes ยุคแรก ไม่มีใน OAuth ยุคแรก — MCP เป็น exception

ผลกระทบจริง ๆ ต่อ team ที่ deploy MCP server: **migration cost จะหนัก**. RC ลบ initialize handshake = **breaking change**. Server ที่ deploy แล้วต้อง dual-stack ทั้ง spec เก่า + spec ใหม่ในช่วง transition (ทำได้ผ่าน `_meta.protocolVersion`), แต่ enterprise SRE team ที่เพิ่ง set up sticky session + Redis session store ต้องเริ่มใหม่. Cloudflare + WorkOS น่าจะ ship migration guide + automation tool ใน 2 สัปดาห์ — vendor lock-in ตามมาทันที

มุมที่ลึกกว่า: **server-as-agent pattern** ที่ RC นี้ promote อย่างชัดเจน — server สามารถ include tool definitions ใน sampling request (ส่วนที่ยังไม่ deprecate), specify tool choice, ทำ multi-step reasoning ภายในตัวเอง. "Research server ที่ spawn agents, coordinate work, deliver coherent result ผ่าน standard MCP primitives โดยไม่ต้องเขียน orchestration code" — นี่คือ **agentic composition layer ระดับ industry standard** ที่ build ได้บน HTTP infrastructure ปกติ

Signal ที่ตามมา: **competing protocol อยู่ในที่ harder position**. Google's A2A v1.0 (production 150 org), NVIDIA OpenShell, OpenAI Agents SDK — ทุกตัวจะถูกถามว่า "ทำไมไม่ใช้ MCP 2026-07-28?" — และต้อง justify ด้วย feature ที่ MCP ไม่มี. ของจริงคือ A2A → MCP มี mapping ที่ Google เพิ่ง publish เมื่อ Q2

## มุม OpenBridge

ตรงเข้า workflow ของเรา: ถ้า OpenBridge มี integration หรือ workflow ที่ expose ผ่าน MCP — เริ่ม **plan migration ไป spec 2026-07-28 ภายในสิ้นเดือนนี้**. การ refactor จาก session-ful → stateless = code change ใหญ่กว่า hot fix; แต่ payoff คือ **deploy บน serverless / edge ได้ตรงไปตรงมา** (Cloudflare Workers, Vercel Functions) ที่ก่อนหน้านี้ต้อง work around session affinity

มุมที่สำคัญสำหรับ positioning: **MCP Apps extension เปิดประตูให้ workflow tool ship UI ผ่าน protocol**. ถ้า OpenBridge มี customer ที่เชื่อม MCP server ของเราจาก Claude Desktop / Cursor / Continue — เราสามารถ ship form, dashboard, approval flow ผ่าน sandboxed iframe ได้โดยไม่ต้องให้ user ออกจาก agent context. นี่คือ **distribution surface ใหม่ระดับเดียวกับ Slack app ในปี 2018** — vendor ที่เคลื่อนช้าจะถูก vendor ที่เคลื่อนเร็วทับ. ลอง prototype MCP App หนึ่งตัว สัปดาห์หน้า — ใช้เวลา 2-3 วัน เห็นมูลค่าจริงหรือไม่จริงทันที
