# Mastercard AP4M + Visa Intelligent Commerce พร้อม OpenAI partnership — payment networks กดเปิด agent-to-agent payment rail วันเดียวกัน

## TL;DR
- 10 มิ.ย. ที่ Visa Payments Forum ทั้ง Mastercard และ Visa เปิด agentic-commerce rail ในวันเดียวกัน Mastercard ปล่อย Agent Pay for Machines (AP4M) ร่วมกับ 30+ พาร์ทเนอร์, Visa ประกาศ Intelligent Commerce + ดีลกับ OpenAI
- Mastercard บันทึก agent credential ลง public blockchain (Polygon, Solana, Base), settle ผ่าน card/account/stablecoin หลาย rail พาร์ทเนอร์: Stripe, Adyen, Coinbase, Ripple, Cloudflare, Ant International, Anchorage
- Visa มี stablecoin annualized run-rate ~$7B (มี.ค. 2026), 160+ stablecoin-linked card programs live; ดีล OpenAI เปิดทาง AI agent ใช้ Visa จ่าย merchant ใน OpenAI platform

## เกิดอะไรขึ้น

วันที่ 10 มิ.ย. 2026 ที่ Visa Payments Forum ใน San Francisco, **Visa และ Mastercard เปิด agentic commerce infrastructure ในวันเดียวกัน** ทั้งสองเจ้าเลือกวันเดียว เลือก message เดียวกัน — agent-to-agent / machine-to-machine payment เป็น category ใหม่ที่ payment network ต้องอยู่ในนั้น และไม่อยากเสีย ground ให้กับ Stripe/Adyen ที่กำลัง integrate AI agent ตรง ๆ

**Mastercard ปล่อย Agent Pay for Machines (AP4M)** — protocol ที่ AI agent สามารถ authorize, coordinate, และ settle transaction บน Mastercard network ได้ที่ "machine speed" รวม microtransaction ระดับ fraction-of-a-cent ที่ใช้ใน agent-to-agent context Stack ทำงาน 3 ชั้น: **Verifiable Intent framework** (credentialing ของ agent), **programmable permissioning** (spending limit + merchant restriction), และ **multi-rail settlement** (card, bank account, stablecoin) ที่ controversial ที่สุดคือ Mastercard เลือกบันทึก agent credential + permission ลง **public blockchain** — เริ่มที่ Polygon, Solana, และ Base — ไม่ใช่ private database ของ Mastercard ทำให้ third party ทุกเจ้าตรวจสอบ permission ของ agent ได้โดยไม่ต้องผ่าน Mastercard API พาร์ทเนอร์ที่ launch วันแรกมีมากกว่า 30 ราย รวม **Stripe, Adyen, Coinbase, Cloudflare, Ant International, Anchorage Digital, Aave Labs, Polygon, Ripple, Solana Foundation, MoonPay** และอีกหลายราย

**Visa ฝั่งตัวเอง** เปิด 3 ของใหม่: **Visa Intelligent Commerce** (trust + control + connectivity layer สำหรับ agent), **Large Transaction Model** (AI model train บน billion-scale transaction เพื่อ fraud detection + reduce false decline), และ **CLI proof-of-concept** ที่ AI agent จ่าย digital service ผ่าน terminal ด้วย Visa tokenized credential ตรง ๆ ดีลใหญ่สุดคือ **partnership กับ OpenAI** ที่ Visa จะให้ network + credentialing + security infrastructure รองรับ "agentic commerce experience" บน OpenAI platform — Seeking Alpha + Stocktwits รายงานว่า user-defined controls (spending limit, merchant restriction, approval requirement) เป็น core ของ design ตัวเลข stablecoin ของ Visa ที่ public ออกมา: **annualized run-rate ~$7B** (ตามรายงาน มี.ค. 2026), **160+ stablecoin-linked card program** live หรือ in development ทั่วโลก, **tokenized deposit** ที่จะทำให้ bank deposit กลายเป็น "programmable, always-on digital money"

ที่ pattern น่าสนใจที่สุดคือ Mastercard และ Visa **share partner ฝั่ง stablecoin/fintech กันเยอะมาก** — Stripe, Coinbase, MoonPay อยู่ทั้งสองข้าง สามวันก่อนหน้านี้ (3 มิ.ย.) PYMNTS รายงานว่า Stripe + Visa + Mastercard + Coinbase กำลังร่วมหนุน stealth stablecoin platform เดียวกัน — แปลว่าใต้ branding ที่แข่งขัน ใต้ infrastructure ที่ collaborate

## ทำไมสำคัญ

นี่คือสัญญาณว่า **AI agent payment เป็น category ที่ payment incumbent ตัดสินใจว่าจะไม่ปล่อยให้ crypto-native + Stripe ผูกขาด** — 6 เดือนที่ผ่านมา narrative คือ "agent จะจ่ายเงินผ่าน stablecoin บน Coinbase/Base/Solana, payment network ใหญ่ตามไม่ทัน" Mastercard และ Visa เปิดวันเดียวกันคือการ flip narrative — ทั้งสองเจ้า embrace stablecoin (Visa ถึงขั้น tokenize bank deposit) และ embrace public blockchain (Mastercard บันทึก credential บน Polygon/Solana/Base) แทนที่จะ defend ของเก่า Coindesk + PYMNTS ที่ track เรื่องนี้มาตลอดบอกตรง ๆ ว่า "crypto rails กำลังเป็น default payment layer สำหรับ AI agent" — Mastercard/Visa ตัดสินใจร่วมแทน defend

จุดที่ commoditize ไม่ใช่ network แต่เป็น **agent identity + intent verification** Mastercard's "Verifiable Intent" และ Visa's user-defined control framework ทำงานเดียวกัน — ต้องตอบ "agent ตัวนี้คือใคร, ได้รับ permission อะไร, จ่ายเงินใครได้/ไม่ได้" — ถ้าใครชนะ trust layer นี้ก็ชนะ rail นั้น stablecoin settlement เป็น commodity layer ใต้, agent intent verification เป็น defensible layer ด้านบน ที่น่าจับตา: ทั้งสองเจ้ารวมเรื่อง **fraud + chargeback** ในระดับ machine speed — agent ที่ผิด policy ต้องโดน reverse ภายในไม่กี่ ms ไม่ใช่ 30 วันแบบ card dispute เดิม

OpenAI deal ของ Visa ส่ง signal ที่ stratech กว่า — OpenAI กำลังจะมี payment surface ของตัวเอง ChatGPT shopping/agent ที่ recommend สินค้าจะปิด loop จ่ายเงินใน app เลย ไม่ต้อง redirect ออก Visa เอา network เข้าไปอยู่ใน OpenAI session — เหมือนที่ Visa อยู่ในเครื่อง POS แต่เป็น "POS = chat session" สำหรับ Mastercard ที่ไม่มี OpenAI deal ในการ ประกาศวันเดียวกัน ต้องตอบให้ได้ว่า 30+ partner ของตัวเองจะ aggregate demand ได้มากกว่ามั้ย

## มุม OpenBridge

OpenBridge ไม่ได้อยู่ใน payment layer ตรง ๆ — แต่ **agent payment infrastructure คือ canonical use case ของ agent integration ที่ต้องการ neutral layer** ที่ pattern ของ Mastercard/Visa ส่งสัญญาณคือ ทุก agent action ที่มี financial side effect ต้องผ่าน intent verification ที่ portable ระหว่าง vendor OpenBridge ออกแบบ workflow ใน B2B context ก็เจอ same pattern — agent ที่ trigger "ส่ง invoice", "approve PO", "เปลี่ยน contract" ต้องมี audit trail ที่ enterprise + counterparty ตรวจสอบได้ pattern "เขียน intent ลง blockchain ที่ third party ตรวจสอบได้" ของ Mastercard เป็น playbook ที่ enterprise integration layer ควรเรียนรู้ — ไม่จำเป็นต้องใช้ blockchain จริง แต่ต้องมี **immutable, verifiable, multi-party-readable record** ของ agent intent

อีกมุมที่ตรงกว่า: **30+ partner ของ AP4M รวม Cloudflare** Cloudflare เพิ่ง publish enterprise MCP reference architecture (Code Mode 99.9% token reduction) เมื่อปลายเดือนพฤษภาคม — ตอนนี้ Cloudflare เข้ามา agent payment ด้วย แปลว่า Cloudflare กำลัง position ตัวเองเป็น "network layer for agent" ที่ครอบทั้ง MCP + payment OpenBridge ต้องตัดสินใจชัด ๆ ว่าจะ partner Cloudflare แบบ application layer (ใช้ network ของเขา, application ของเรา) หรือ compete ที่ partial overlap — ตามที่ผมเคยแนะนำใน brief 31 พ.ค. 6 สัปดาห์ที่แล้ว pattern นี้ขยายลึกขึ้นอีก ต้องตัดสินใจในรอบ Q3 นี้
